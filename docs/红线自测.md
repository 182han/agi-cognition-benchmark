# 三条红线逐条自测

> 依据《Elite20 挑战提交总则 v1.3》§8。每条红线给出：**自查问题 → 我的做法 → 可复核的证据
> → 仍然存在的残余风险**。最后一项不写"无风险"——那等于没自查。

---

## 红线 1：AI 日志缺失或伪造

**自查问题**：AI 日志里的每个决策节点，是不是真实发生过的？有没有为了好看而补写？

**我的做法**

- 两份日志共 **17 个决策节点**（C2A 7 个 + C9 10 个），格式统一为
  「背景 / AI 建议 / 我的判断 / 人工核验 / 结果」。
- **明确写出 AI 被驳回的次数**（C2A 3 次、C9 4 次），并写清驳回理由。
- **明确写出 AI 最大的误导**：两次都是"把指标异常解释成任务更难，而不是怀疑检查写错了"。
- 日志里出现的每个数字都是从真实运行里拷出来的（生成耗时、拒绝统计、等价类数量、
  正确率），不是估计值。

**证据**

| 证据 | 位置 |
|---|---|
| C2A 日志 7 节点 + AI 使用统计表 | `赵怡涵_C2A_AI日志.md` |
| C9 日志 10 节点 + AI 使用统计表 | `赵怡涵_C9_AI日志.md` |
| 决策节点 5 里记录的"B 阶段 100% / C 阶段 83%"与随后的效度漏洞定位 | `赵怡涵_C9_AI日志.md` |
| 决策节点 10 里记录的"批次相邻泄漏 → Phase A 隔离重跑" | `赵怡涵_C9_AI日志.md` |
| 日志末尾附的真实命令清单 | 两份日志的「附」一节 |

**残余风险**：日志由我（借助 AI）撰写，**评审无法独立验证会话过程**。可交叉验证的是
日志里提到的每个数字都能在本包里被复算（如 `data/manifest_*.json` 的 `reject_stats`
与日志里写的一致）。我尽量把可核验的数字留在日志里，就是为了让这一点可查。

## 红线 2：伪拿来（假装借鉴，其实是自己造或抄而不说）

**自查问题**：拿来说明里的每个来源，是不是真的存在？我到底拿了什么、改了什么？

**我的做法**

- 让一个**独立的联网核查子任务**逐条核查 15 项文献的标题/作者/年份/会议或 arXiv 编号/
  URL/主张，并打「已核验 / 部分核验 / 未核验」标签。**这是本包里我最重视的一步。**
- 核查结果抓出**两条我原本要写的假引用**：
  - "Beyond the **Imprint**: BIG-Bench" —— 不存在，真名是 *Beyond the **Imitation
    Game***（arXiv:2206.04615）；
  - "**Ambiguity in In-Context Learning**" —— 不存在这个标题，真正相关的是 Tamkin et al.
    的 *Task Ambiguity in Humans and Language Models*（ICLR 2023）。
- 还有**一条被降级**：DeepMind 认知框架真实存在，但流传的「2026 年 + arXiv:2605.28405」
  只有弱证据 → 最终引用**只写博客链接，不写那个 arXiv 编号**。
- canary GUID **不冒用 BIG-bench 官方 hex 字符串**（无法逐字确认），改用本基准自造 GUID。
- 「没有拿的东西」单独成节，写清为什么不要（不是忘了）。

**证据**

| 证据 | 位置 |
|---|---|
| 13 条来源的可点击链接 + 「拿了什么」 | `赵怡涵_C2A_拿来说明.md` §一 |
| **核验记录**（含两条错误引用的原始错误写法与纠正） | `赵怡涵_C2A_拿来说明.md` §二 |
| 「拿不来的部分」逐条对照表 | `赵怡涵_C2A_拿来说明.md` §三 |
| 实现层的借鉴（代码/算法/工程实践）与自创部分分离 | `赵怡涵_C9_拿来说明.md` §二、§三 |
| 「明确没有拿的东西」 | 两份拿来说明各自末节 |

**残余风险**：核查依靠检索结果交叉比对，**没有逐篇打开原文页面**（本机无外网抓取能力）。
被标为「部分核验」的字段在正式引用前应再打开链接确认一次。这一点已写进拿来说明。

## 红线 3：不可复现

**自查问题**：评审在自己的机器上能不能跑出同样的东西？脚本会不会"打印警告然后 exit 0"？

**我的做法**

- **一条命令**：`bash scripts/reproduce.sh`（包级 wrapper）→ 委派给基准流水线 →
  跑数据/解题器/审计/自检/汇总榜 → 再跑两层冒烟测试。
- **失败必须非零退出**：脚本用 `set -euo pipefail`，任何一步失败就 `exit 1`，
  不使用「打印警告然后 exit 0」的写法（那正是这条红线惩罚的静默故障）。
- **零第三方依赖**：只用 Python 标准库 → 不存在"装不上就复现不了"。
- **确定性**：生成器同 seed 两次生成**字节一致**（流水线里每次都复核并打印哈希）；
  所有随机都走 seeded RNG。
- **反向核验答案**：`rule_text` 能被反向解析、重新施加到查询上、与答案比对 →
  答案不是"需要相信"的断言。此检查在全量 84 题上跑。
- **结果可复算**：所有指标都从 `data/` + `keys/` 重算，不是硬编码在文档里的数字。

**证据**

| 证据 | 位置 |
|---|---|
| 一条命令入口 | `scripts/reproduce.sh`、`赵怡涵_C9_benchmark/scripts/reproduce.sh` |
| 真实终端输出（含哈希比对） | `赵怡涵_C9_benchmark/README.md` 的「验证」一节 |
| 生成器确定性哈希 | 同上；另见 `CHANGELOG.md` 的 D4 |
| 答案可核验 | `bench/selfcheck.py` S2、`tests/test_smoke.py` |
| 可归纳性复核 | `bench/selfcheck.py` S5 |
| 防污染审计 | `bench/contamination.py` A1–A7 + `docs/防作弊报告.md` |

**残余风险**：

1. `holdout` 分片需要 `DRBENCH_HOLDOUT_SEED` 才能重生成。种子已在
   `data/manifest_holdout.json`（`seed: 255399336`）里公开，**先承诺的哈希**在
   `data/holdout_seed_commitment.json` 里，两者对得上才说明没被事后更换。
2. CPU 性能会影响 `search` 解题器的运行时间（本机约 2 分钟/分片），但不影响结果——
   搜索是确定性的，与机器无关。
3. `--fast` 模式会跳过最重的解题器；完整模式才是完整复现。这一点在脚本帮助里写明了。
